# ToDo

## Where things stand

- **Foundations.** The repository, the CMake build and continuous integration on Mac, Windows and Linux are in place, with a contributing guide and issue and pull request templates. The core module has its first parts: values with JSON, XML documents, UTF-8 text, paths and the system's folders, files written safely, settings files, SHA-256, and speaker layouts.
- **Audio files.** The files module reads and writes WAV, including RF64 past 4 GB with its broadcast extension and other chunks kept, AIFF and AIFF-C, and FLAC, Ogg Vorbis and Opus with their tags, a stretch at a time, and writes a recording from an audio device's thread, flushed every second. It reads MP3 gaplessly, and M4A, AAC and CAF through the systems' own decoders on Mac and Windows.
- **Web pages.** The ui module shows pages in the system's own web view on Mac and Windows, served from files built into the program, with calls and events between page and native code, in a program's own windows or a plugin host's. Plugin editors are web pages built on it, and the Filter example has one.
- **Programs.** The ui module runs the message loop, with calls to its thread from any other and timers, and the app module makes a desktop program of an executable on Mac and Windows: the system's requests to quit, to open files and to come back, one instance at a time with a second handing its arguments to the first, and the application bundle or the Windows program built by `symbolengine_add_app`. The Hello example is one.
- **Plugins.** The plugin module builds CLAP, VST3 and Audio Unit plugins from a class written once, and keeps a VST3 class ID and Audio Unit codes a plugin was released with. Buses take any standard layout from mono to 7.1.4 in every format, Dolby's 9.1.4 and 9.1.6 in VST3 and Audio Units, and the ITU 9.1.6 in CLAP and VST3, through SymbolEngine's fork of clap-wrapper. The Gain and Filter examples pass CLAP's validator, Steinberg's, pluginval at its strictest level and auval. A plugin released before keeps the state hosts saved of it and its parameter numbers, as Symbol Studio's four plugins do, checked against a Live set saved with their earlier builds.
- **Devices.** The devices module's lessons are written into the architecture, every problem audio software has met with Core Audio, Windows Audio and ASIO and in the layer above them, each with its test. The layer above the systems is built and passes its tests against a scripted fake system: device lists, saved setups found again, each stream's control thread and events, and a timeline that counts every lost frame and says every dropout, stall and loss. Core Audio lists a Mac's devices and plays through them, and Windows Audio lists a PC's endpoints, plays through them and records from them, its input losing nothing to a thread held up for 50 ms. A player plays files through them with a read-ahead, at the device's rate whatever the file's. A Mac's input is refused when the user hasn't allowed the microphone, where Core Audio would give silence. ASIO is built with the developer's SDK and passes its tests against fake drivers, and records from the owner's Focusrite through its own driver. Symbol Studio plays and records through all of it, an hour's take on Windows within 1 part per million of the clock and an hour on the Mac to the millisecond. Streams say when the system mutes a program's input, stop an idle output's device until something plays, follow the default output when asked, and give worker threads the device's workgroup; Windows Audio's exclusive mode and raw stream and ASIO's control panel are done. Built since: an input and an output on two clocks with the drift corrected, a recorder of real hardware's notices for the fake to replay, and Multi-Output devices and aggregates checked on BlackHole's loopback devices; sleep, unplugging and a Bluetooth headset tried with the owner on the Mac and Windows. Those sessions are kept as tests the fake replays. Windows starts a USB interface's input with 270 ms of exact zeros, which a take that carries on keeps as they came.
- **Hosting.** The lessons for hosting other makers' plugins are written into the architecture's [hosting](02_architecture.md#hosting) section, each with its test: 180 problems other hosts have met with VST3, Audio Units and CLAP, with scanning in worker processes and with loading other makers' code into a program, read from their histories of fixes, the formats' documentation and a scan of a library of over a thousand plugins. The code has begun with its tests first: core starts child processes and keeps a link to them, the base of the scan's workers, and the host module has its format layer, a fake format whose plugins check every call made into them, each plugin's life on the main thread with its processing on the audio thread, and VST3 plugins made, arranged, played and saved, their parameters listed, set and automated at their frames, their own edits and the values they report reaching the program, where the program is in time given in every call, and a plugin that throws, or on Windows crashes, switched off with the program going on, checked against test plugins of its own; and the list a scan keeps of the plugins it found, the files it looked at and why any were set aside, which damage to its file costs only the entries it touches, and the worker process that loads each file for a scan, so a plugin that crashes or hangs takes down only it, with the scan that drives the workers, setting aside only the plugin at fault, and the walk of the plugin folders that finds what to scan.
- **The first release** comes when Symbol Studio runs on SymbolEngine alone, and the phases below follow what it needs, plugins first and hosting other makers' plugins last.
- **Home.** The name is SymbolEngine, symbolengine.dev is registered, the license is MIT, and the code is public at github.com/cybra/symbolengine. Contributions are signed off under the Developer Certificate of Origin.
